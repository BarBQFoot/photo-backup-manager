# ทดสอบคำบรรยายจากภาพด้วย Florence-2

ใช้โมเดลที่ดาวน์โหลดไว้ `florence-community/Florence-2-base-ft` และแพ็กเกจใน `.venv` เดิม สคริปต์อ่านไฟล์ในเครื่อง ไม่เรียก Gemini และไม่แก้ฐานข้อมูลแอป

## เริ่มจาก 10 รูป

เปิด PowerShell ในโฟลเดอร์โปรเจกต์:

```powershell
.\.venv\Scripts\python.exe -u tools/caption_images.py --input test-images/50 --pilot
```

`--pilot` เลือก 10 รูปที่กำหนดไว้จากชุด 50 ได้แก่ ภาพสัตว์ ถนน ห้องครัว หิมะ คนบนโซฟา ภาชนะ เครื่องใช้ กีฬา และชายหาด ชื่อหมวดนี้ใช้เลือกชุดทดสอบเท่านั้น ไม่ส่งเป็นคำใบ้ให้โมเดล ชุดนี้ไม่ใช่ตัวอย่างที่เป็นตัวแทนทางสถิติ

โหลดโมเดลหนึ่งครั้งแล้ววนทีละภาพ ใช้ `<CAPTION>`, `num_beams=3`, `max_new_tokens=64`, `do_sample=False` เหมือนคำสั่งที่ผู้ใช้ทดลองภาพโซฟา หากต้องการทดลองกับไฟล์ส่วนตัวใช้ `--input <โฟลเดอร์รูป>` และ `--limit 10` แทน `--pilot`

## ผลลัพธ์

สร้างโฟลเดอร์ใหม่ `results/florence_<วันเวลา>` ทุกครั้ง:

- `captions.csv`: เปิดดูชื่อรูป คำบรรยายภาษาอังกฤษ และเวลาได้
- `captions.json` และ `photos/<file_id>.json`: คำบรรยายพร้อมพาธและข้อมูลการประมวลผล
- `summary.json`: จำนวนสำเร็จ/ผิดพลาด เวลาโหลดโมเดล เวลาประมวลผล และเวลาเฉลี่ย
- `errors.json`: รูปที่ประมวลผลไม่ได้
- `translation_payloads.json`: รหัสรูปและคำบรรยายภาษาอังกฤษสำหรับขั้นเรียบเรียง/แปลภายหลัง ใช้ฟิลด์ caption_en ซึ่งต่างจาก payload คำสำคัญในระบบทดลองก่อนหน้า

ต้องตรวจภาพเทียบคำบรรยาย โดยเฉพาะวัตถุ ท่าทาง ตำแหน่ง จำนวน และรายละเอียดที่โมเดลเพิ่มเอง การแปลด้วย Gemini ไม่สามารถยืนยันความถูกต้องของคำบรรยายต้นทางได้ `possible_truncation` เป็นเพียงสัญญาณว่าอาจชนลิมิตโทเคน ไม่ใช่คะแนนความถูกต้อง

เวลาต่อรูปเริ่มก่อนเปิดไฟล์และสิ้นสุดหลังสร้าง/ถอดคำบรรยาย ไม่รวมโหลดโมเดลและเขียนรายงานของรูปนั้น เวลารวมของสคริปต์เริ่มก่อนโหลดโมเดล ไม่รวม import ก่อน main และไม่รวม Gemini ภาพแรกอาจรวมเวลาเตรียมการของ GPU จึงต้องดูค่าเฉลี่ยหลายภาพ

## ทดสอบชุดใหญ่หลังตรวจคุณภาพ

```powershell
.\.venv\Scripts\python.exe -u tools/caption_images.py --input test-images/50
.\.venv\Scripts\python.exe -u tools/caption_images.py --input test-images/100
.\.venv\Scripts\python.exe -u tools/caption_images.py --input test-images/1000
```

`--device auto` เลือก CUDA/MPS/CPU ตามที่ตรวจพบ ใช้ float16 บน CUDA และ float32 บน CPU/MPS หาก backend ไม่รองรับ operation ให้ทดลอง `--device cpu` ยังต้องทดสอบจริงบน macOS/Linux ก่อนรับรองการรองรับข้ามระบบ ใน macOS/Linux เรียก Python ด้วย `./.venv/bin/python` แทนพาธ Windows และเตรียม environment/model cache บนเครื่องนั้นก่อน

เวลาประมาณ 76 วินาทีที่วัดจากระบบ YOLO/Places365/SigLIP2 ใช้แทนเวลา Florence ไม่ได้ และภาพโซฟา 2.939 วินาทีเป็นผลจากภาพเดียว ยังไม่ใช่ benchmark ของชุดนี้

ผล 50 รูปอยู่ใน `results/florence_20261022_155219_469665` ภาพแรกใช้ 2.901 วินาที ภาพถัดไปส่วนใหญ่ประมาณ 0.2–0.3 วินาที ไม่ใช่การวัดความแม่นยำ ยังไม่ได้รัน Florence 100 รูปหรือทดสอบ Mac/Linux

ผล 1000 รูปที่ผู้ใช้รันอยู่ใน `results/florence_20261022_222031_582707` ใช้เวลารวมตามสคริปต์ประมาณ 5 นาที 44 วินาที สำเร็จครบ ไม่มีข้อผิดพลาด ไม่มีสัญญาณชนลิมิตโทเคน ตรวจ 1000 IDs ไม่ซ้ำและตรง source manifest, มีรายงานต่อรูปครบ และคำบรรยายอังกฤษไม่ว่างทุกภาพ ค่าเฉลี่ยต่อภาพที่รายงาน 0.339 วินาที เป็นผลรอบเดียวและไม่รวมการแปล Gemini

เตรียม `translation_batches` ไว้แล้ว 20 ชุด ชุดละ 50 รายการ ตรวจการนำทุกชุดมาต่อกันตรงกับ source payload ทุกตัวอักษรและพรอมป์ต์แนบข้อมูลถูกชุด รายงานตรวจอยู่ใน `verification.json` ไม่มีการเรียก Gemini API หรือส่งภาพออกไปจากสคริปต์

ตรวจภาพ pilot 10 รูปด้วยสายตาแล้วพบว่าใจความหลักสอดคล้องกับภาพ แต่ไม่ใช่คะแนน benchmark และตรวจเพิ่มแล้วพบคำบรรยายผิดในภาพ `000000139099.jpg`: โมเดลกล่าวว่าสุนัขอยู่ด้านหลังสกู๊ตเตอร์ ขณะที่ภาพเห็นสุนัขอยู่ในตะกร้าด้านหน้า คำบรรยายต้นทางยังเก็บตามที่โมเดลสร้าง ไม่มีการแก้เฉพาะภาพเพื่อทำให้ผลดูดีขึ้น ต้องแยกตรวจความถูกต้องกับภาพออกจากคุณภาพการแปล

## เตรียมแปลภาษาไทยเป็นชุด

สร้างไฟล์ข้อความพร้อมข้อมูลจริงครั้งละ 50 รายการ ไม่เรียก API:

```powershell
.\.venv\Scripts\python.exe tools/prepare_translation.py --run results/florence_20261022_155219_469665
```

สร้าง `translation_batches/batch_001.json` และ `batch_001_prompt.txt` ภายในโฟลเดอร์รอบนั้น หากเคยสร้างโฟลเดอร์ translation_batches แล้วสคริปต์จะหยุดเพื่อไม่เขียนทับ เปลี่ยนขนาดชุดด้วย `--batch-size 100` ได้

คัดลอกข้อความจาก `batch_001_prompt.txt` ทั้งหมดไปลองใน Gemini พรอมป์ต์ใช้ caption_en เป็นแหล่งข้อมูล ไม่เพิ่มรายละเอียดใหม่ และไม่มีตัวอย่างคำตอบ ชุดแปลมีเฉพาะรหัสกับคำบรรยายภาษาอังกฤษ ไม่แนบรูปหรือพาธไฟล์ส่วนตัว การแปลไม่ได้แก้ข้อผิดพลาดด้านเนื้อหาที่เกิดจาก Florence

เก็บคำตอบในโฟลเดอร์ `translation_responses` แล้วตรวจด้วยสคริปต์เดิมที่รองรับทั้ง keyword payload และ caption_en:

```powershell
.\.venv\Scripts\python.exe tools/validate_captions.py --request results/florence_20261022_155219_469665/translation_batches/batch_001.json --response results/florence_20261022_155219_469665/translation_responses/batch_001_response.json --report results/florence_20261022_155219_469665/translation_responses/batch_001_validation.json
```

การตรวจนี้รับรองรูปแบบและการจับคู่ IDs เท่านั้น ยังไม่ตรวจภาษาไทยว่าแปลตรงต้นฉบับหรือบรรยายตรงภาพ
