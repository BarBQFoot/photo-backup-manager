# ใช้ Florence และ Gemini แบบชุดในแอป

ปุ่มวิเคราะห์ในแกลเลอรีเรียก `AnalyzeImages` ครั้งเดียวสำหรับรูปที่เลือก Go จับคู่ด้วย ID ในฐานข้อมูล ไม่ใช้ชื่อไฟล์หรือ ID ของชุด COCO ทดสอบ Python เก็บ Florence ไว้ใช้ซ้ำใน process เดิม สร้างคำบรรยายอังกฤษบนเครื่อง แล้วส่งเฉพาะ `file_id` กับ `caption_en` ไป Gemini ครั้งละไม่เกิน 100 รายการ พัก 10 วินาทีระหว่างชุด ค่าเริ่มต้น `gemini-3.5-flash-lite`

ผลแปลที่ผ่านการตรวจ ID บันทึกกลับฐานข้อมูลทีละผล หน้าจอแสดงความคืบหน้าช่วงอ่านภาพและแปล หากชุดใดหยุดกลางทาง ผลที่สำเร็จยังอยู่ เลือกเฉพาะรูปที่ไม่สำเร็จแล้วกดอีกครั้งได้ ตรวจ ID ไม่ซ้ำ ตรวจรูปยังอยู่ที่เดิมและขนาด/เวลาแก้ไขไม่เปลี่ยนก่อนบันทึก

ถ้า Gemini ตอบ JSON หรือ ID ผิด ระบบเก็บคำตอบที่ผิดไว้เพื่อวินิจฉัย และส่งชุดเดิมซ้ำได้อีก 1 ครั้งหลังพัก 10 วินาที หากยังผิดจะหยุดโดยเก็บชุดที่สำเร็จไว้ เลือกรูปที่ไม่สำเร็จเพื่อทำต่อได้ ไม่ต้องล้างแคชหรือผล 700 รูปที่สำเร็จแล้วในกรณีที่หยุดหลังชุดที่ 7

## เริ่มบนเครื่องพัฒนา Windows

ใช้ `.venv` และโมเดลที่ดาวน์โหลดไว้แล้ว ตั้ง `GEMINI_API_KEY` ใน `.env` ที่ root โครงการตามเดิม:

```powershell
wails dev
```

เปิดโฟลเดอร์ปลายทางในแกลเลอรีที่มีรูปและ metadata จากการย้าย/สำรองแล้ว เลือก 2–5 รูป กดวิเคราะห์รูปที่เลือก ตรวจว่ามีคำอธิบายไทยและค้นด้วยคำนั้นได้ก่อนเพิ่มจำนวน รูปที่สแกนได้แต่ยังไม่มี fileId ต้องผ่านขั้นย้าย/สำรองของแอปเพื่อสร้าง metadata ก่อน

แอปค้นหา Python ใน `.venv` ของโครงการหรือใกล้ executable ถ้าหาไม่เจอ กำหนดพาธชัดเจนก่อนเปิด:

```powershell
$env:PHOTO_AI_PYTHON = (Resolve-Path .\.venv\Scripts\python.exe).Path
wails dev
```

ตัวแปรเลือกเพิ่มเติม (ไม่จำเป็นต้องตั้งทุกตัว):

| ตัวแปร | ความหมาย |
| --- | --- |
| `PHOTO_AI_PYTHON` | executable ของ Python ที่ติดตั้ง torch, transformers, Pillow แล้ว |
| `PHOTO_AI_CACHE` | โฟลเดอร์เก็บ cache เขียนได้ ถ้าไม่ตั้งใช้ user cache/photo-backup-manager/ai |
| `GEMINI_TRANSLATION_MODEL` | เปลี่ยนโมเดลแปล ค่าเริ่มต้น gemini-3.5-flash-lite |
| `GEMINI_API_KEY` | คีย์สำหรับแปลข้อความ รับจาก environment ของแอป |

บน Windows cache เริ่มต้นอยู่ใต้ `%LOCALAPPDATA%\photo-backup-manager\ai` เก็บคำบรรยายอังกฤษและไทย แยกด้วย SHA256 เนื้อหารูปและการตั้งค่าโมเดล/พรอมป์ต์ เพื่อกดทำต่อโดยใช้ผลที่บันทึกแล้ว รูปเหมือนกันแต่ ID หรือพาธต่างกันใช้ผลเดิมได้ การแก้รูปทำให้ cache เปลี่ยน ไม่ต้องลบ cache เพื่อทำต่อ

ไฟล์รูปไม่ถูกส่งให้ Gemini คำบรรยายภาษาอังกฤษถูกส่งเพื่อแปล การกดปุ่มวิเคราะห์จึงยังใช้โควตา Gemini ตามจำนวนชุดและการ retry (ไม่เกินหนึ่ง retry ต่อชุด) รอ 10 วินาทีระหว่างชุด (ปรับจาก 30 วินาทีวันที่ 23 ตุลาคม 2026 ตามผู้ใช้) และอย่างน้อย 60 วินาทีเมื่อ HTTP 503 Timeout 300 วินาที หาก HTTP 429 มีเวลารอที่ผู้ให้บริการระบุ จะยังเคารพเวลานั้น ไม่ได้จำกัด retry ให้รอเพียง 10 วินาที เมื่อ timeout จะหยุดเพราะไม่รู้ว่าฝั่งผู้ให้บริการประมวลผลแล้วหรือยัง การกดทำต่ออาจต้องส่งชุดนั้นใหม่และนับโควตาอีก

## การแจกแอปและระบบอื่น

สคริปต์ Python และพรอมป์ต์ฝังใน Go executable แล้วและแตกออกใน user cache เมื่อใช้งาน ไม่จำเป็นต้องแจก source tools/docs แยก รุ่นปัจจุบันมีหน้าจอเตรียม AI ครั้งแรกที่ตรวจของเดิมและดาวน์โหลด Python/ไลบรารี/Florence เฉพาะส่วนที่ขาด ไม่รวมโมเดลหลาย GB ไว้ใน executable ดู [วิธีเปิด EXE](RUN-WINDOWS-EXE.md) การใช้ `.venv` ที่เตรียมเองยังทำได้ตามเดิม

บน macOS/Linux กำหนด `PHOTO_AI_PYTHON` ให้ชี้ `.venv/bin/python` ของเครื่องนั้น และโหลดโมเดลเข้าบัญชีผู้ใช้ที่รันแอป Florence เลือก CUDA ถ้ามี ตามด้วย MPS บน Mac หรือ CPU ถ้าไม่มี GPU ห้ามคัดลอก `.venv` ของ Windows ไปใช้บน Mac/Linux ต้องสร้าง environment ตามระบบ

การกู้สถานะ analyzing ทำระหว่างสแกนเมื่อไม่มีงาน AI ใน process นี้ ถ้าปิดแอปกลางงาน ให้เปิดใหม่แล้วสแกนปลายทางอีกครั้ง สถานะที่ค้างจะกลายเป็น failed เพื่อให้เลือกทำต่อ แอปไม่รองรับหลาย instance เขียนฐานข้อมูลเดียวกันพร้อมกัน

การทดสอบอัตโนมัติใช้ API จำลอง ไม่ใช้คีย์จริง ตรวจ batch 50, ผลตอบกลับสลับลำดับ, cache, timeout/resume, รูปเปลี่ยน และการผูก DB IDs ผลการทดสอบบน Windows ไม่ยืนยันว่าทดสอบใช้งานจริงบน Mac/Linux แล้ว และยังต้องลองปุ่มใน Wails กับ Gemini จริงก่อนรับรอง end-to-end

ผลตรวจวันที่ 23 ตุลาคม 2026:

- `go test ./... -count=1` ผ่านทั้งหมด โดยรันนอก sandbox เพราะ sandbox บล็อก rename ของไฟล์ชั่วคราวและ HTTP fixture ในเทสต์เดิม
- เทสต์ Python translator 17 ข้อ และ desktop worker 4 ข้อ ผ่าน ใช้ API จำลองทั้งหมด
- `npm run build` ผ่าน และสร้าง Wails bindings ใหม่ด้วย `wails generate module`
- ทดสอบ Florence จริง 2 รูปผ่าน worker ใหม่ ได้คำบรรยายคนบนโซฟาพร้อม laptop และม้าลายสองตัว ใช้คำแปลจำลอง ผลอยู่ `results/app-local-ai-smoke/report.json`
- `TestHybridCachedProcessSmoke` ผ่าน การเรียก Python จาก Go และส่ง JSON events กลับทำงาน ใช้ cache ทดสอบแยกและไม่มี API key
- ยังไม่ได้กดวิเคราะห์ในหน้าจอ Wails โดยใช้ Gemini จริง จึงให้เริ่มลอง 2–5 รูปก่อน

## หาก Florence โหลดไม่สำเร็จในหน้าจอ

เมื่อวันที่ 23 ตุลาคม ผู้ใช้พบข้อความรวมว่า Florence โหลดไม่ได้ โค้ดเดิมซ่อน exception จึงยังระบุสาเหตุจากข้อความนั้นไม่ได้ ตรวจใน `.venv` และเพิ่มเทสต์ Go เรียก Python แบบ hidden subprocess ด้วยโมเดลจริงแล้วโหลด/สร้างคำบรรยายได้ เทสต์นี้ลบ API key และหยุดก่อนส่ง Gemini

แก้ให้แสดงชนิด exception, ข้อความจริง และ Python executable พร้อมเก็บ `captions/model_load_error.json` ใต้ AI cache เฉพาะเมื่อโหลดโมเดลล้มเหลว หน้าจอรวมข้อผิดพลาดซ้ำแทนการพิมพ์ข้อความเดิมทุกภาพ เทสต์ offline เพิ่มเป็น 22 ข้อและผ่านนอก sandbox

หากเกิดซ้ำ ให้ปิดแอปเก่า เปิด `wails dev` ใหม่ โดยตั้ง `PHOTO_AI_PYTHON` ชี้ environment ที่ทดสอบไว้ แล้วลองเพียง 1 รูปก่อน ยังไม่ต้องติดตั้งหรือดาวน์โหลดโมเดลซ้ำจนกว่าจะอ่านสาเหตุจริง

### สาเหตุที่พบ: Unknown level: 'Info'

Wails 2.13.0 ตั้ง environment `loglevel=Info` ใน dev mode (`cmd/wails/internal/dev/dev.go`) บน Windows ตัวแปร environment ไม่แยกตัวพิมพ์เล็กใหญ่ PyTorch distributed elastic อ่าน `LOGLEVEL` แล้วส่งให้ Python logging ซึ่งไม่รับ `Info` จึงล้มระหว่าง import ก่อนโหลด Florence

ยืนยันด้วยการเพิ่ม `loglevel=Info` ลงในเทสต์ Go-to-Python กับโมเดลจริงแล้วได้ error เหมือนผู้ใช้ แก้ใน `aiWorkerEnvironment` ให้เอา loglevel ออกจาก environment ของ subprocess เท่านั้น ไม่แก้ค่า logging ของ Wails ตัวแม่ ไม่ต้องโหลดโมเดลหรือติดตั้ง Python ใหม่ หลังแก้ต้องปิดแอปเดิมแล้วเปิด `wails dev` ใหม่
