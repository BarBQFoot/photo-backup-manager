# แก้ progress วิเคราะห์ภาพตามหลังงานจริง

วันที่ 23 ตุลาคม 2026 ผู้ใช้เห็นหน้าแกลเลอรีอ่านภาพ 358/1000 หลังรอประมาณ 6 นาที ตรวจแบบอ่านอย่างเดียวในขณะนั้นพบ cache คำบรรยายอังกฤษ 1000 รูป และ DB ปลายทางมี analyzed 200 / analyzing 800 โดย translation summary กำลังแปลชุดที่เหลือ 900 รายการและแปลสำเร็จแล้ว 100 รายการ รวม cache เดิม 100 รายการ ผู้ใช้แจ้งภายหลังว่ารอบทั้งหมดเสร็จใช้ 17.55 ซึ่งตีความในการสนทนาเป็น 17 นาที 55 วินาที ยังไม่มี stage timing ที่ยืนยันสัดส่วนเวลาของแต่ละขั้น

สาเหตุที่ตรวจพบคือหน้าแกลเลอรีมีรายการรูป 1000 ใบและ checkbox ผูก selectedPaths แบบ array ทุก progress เปลี่ยน busy string ทำให้ render รายการซ้ำ แม้ backend อ่านภาพเสร็จและเข้าสู่การแปลแล้ว

## การแก้

- สร้าง computed Set ของพาธที่เลือก เพื่อไม่ไล่ selectedPaths ซ้ำทีละแถว
- ใช้ v-memo รายรูป ติดตาม object รูป สถานะ AI/ไฟล์ การเลือก การเปิดรายละเอียด และ busy เพื่อให้ผลที่เปลี่ยนอัปเดตได้ แต่ข้ามรูปเดิมเมื่อเปลี่ยนแค่ข้อความ progress
- ลด AI progress counter เป็นประมาณ 10 ครั้ง/วินาที โดยส่งเปลี่ยน phase และ completion ทันที
- ส่ง result ของแต่ละรูปที่บันทึกสำเร็จทุกอันตามเดิม ไม่มีการลดหรือทิ้ง result
- ไม่เปลี่ยน Florence การตั้งค่าโมเดล ขนาด batch Gemini หรือข้อมูลคำบรรยายที่บันทึกไว้

## ผลตรวจ

- `go test ./service -count=1` ผ่าน รวมเทสต์ progress ที่ตรวจว่า counter ถูกรวม แต่ phase/results/completion ไม่หาย
- `npm run build` ผ่าน
- `node tools/profile_gallery_render.cjs` compile หน้า gallery จริงด้วย Vue แล้ววัด in-memory renderer: 1000 ใบ / 20 progress updates โค้ดเดิม 10066 ms เทียบกับหลังแก้ 42 ms
- เทสต์ตรวจ checkbox ที่เลือก การเปลี่ยนสถานะ analyzed การเปิด/ปิดปุ่มตาม busy และสถานะรูป การค้นหาคำบรรยาย และการกรองไฟล์ missing ผ่านทั้งก่อน/หลัง
- ผลวัดข้างต้นไม่รวม native DOM ของ Wails, Florence หรือ Gemini จึงไม่ได้แปลว่าเวลารวม 17:55 จะลดลงในสัดส่วนเดียวกัน ยังต้องลองรอบจริงหลังเปิดแอปใหม่

รายงาน benchmark อยู่ `results/gallery-profile/render.json` ไม่ได้เรียก Gemini หรือเขียน DB ผู้ใช้ในการทดสอบ
